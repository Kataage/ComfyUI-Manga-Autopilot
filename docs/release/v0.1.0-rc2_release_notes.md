# v0.1.0-rc2 Release Notes

**Release date:** 2026-08-28

Second release candidate. rc1 shipped the pipeline; rc2 adds strict Anima
mode and fixes everything that only appeared once the pipeline was run
against real hardware and loaded by ComfyUI itself.

## Highlights

**Strict Anima mode.** Selecting a `generation_profile_id` beginning with
`anima_` turns on structured planning validated against a JSON Schema, a
story bible with a scene-state reducer, layout-aware panel planning, and
generation profiles that own the technical parameters instead of leaving
them to the LLM.

**Four review gates.** Story, Storyboard, Artwork Early and Artwork Final,
with edit-driven invalidation. No image is generated before Storyboard is
approved.

**Reproducibility.** Each run writes a `snapshot.json` carrying SHA-256
fingerprints for every model, the complete rendered prompts, seeds and
dimensions, and the environment - with no credentials. Diagnostic logs
carry prompt hashes rather than prompt text.

**Preflight.** Eight read-only checks before the first panel is queued:
endpoint and auth, licence acknowledgement, model and LoRA files, workflow
bindings against the node classes ComfyUI actually registers, character
references, resolution policy, output directory, and a warning when the
profile renders at CFG 1, where ComfyUI skips the negative branch entirely.

## Proven on hardware

A two-page manga was produced end to end on 2026-08-28: a real LLM planner,
a real GPU (Anima Turbo on an RTX 5070 Ti), all four gates approved over
REST, and page PNGs, a webtoon strip and a PDF out the other end. Panel
rendering measured ~12s each; planning dominated at 66-900s.

That run exposed eleven real defects, seven of which were components that
existed and had passing tests but were never called from the production
path. All are fixed.

## Loaded by ComfyUI

The extension was installed into a running ComfyUI (0.30.0, frontend
1.47.11) and driven in a browser: the sidebar tab registers, all six web
modules are served, and the review editor performs a real HTTP round trip
against the backend. That found three more defects, all fixed:

- No `requirements.txt`. ComfyUI and ComfyUI-Manager install that file and
  do not read `pyproject.toml`, so `jsonschema` was missing and every HTTP
  route failed to register while the sidebar tab still rendered.
- The Projects tab was blocked by the guard only it could clear, so a fresh
  workspace could never set a project id.
- The workspace was ~448px wide inside a 312px sidebar that clips overflow,
  leaving its left edge unreachable.

## Upgrading from rc1

No migration step is required. Projects are migrated lazily on read, and a
byte-identical timestamped backup is written before the first migrated save.

Install with ComfyUI's own interpreter - a portable or desktop ComfyUI ships
its own Python:

```bash
"<comfyui>/python" -m pip install -e .
```

## Known limitations

- `page_count` reaches a run only through the autopilot start body. The
  restart route restores it from `project.json`; start does not, so a
  project started as `docs/anima_mvp.md` describes - with no body - plans
  against `page_count` 1 and any multi-page plan fails validation.
- Establishing shots carry no character anchor by design, and warn.
- Turbo suppression has no scene-independent positive phrasing. At CFG 1
  the negative prompt is not evaluated, and negation in the positive prompt
  renders the thing it names.
- The planner writes little dialogue - three of nine panels in the last
  live run. Inventing the rest is deliberately not implemented.
- Real ComfyUI, Modal and S3/R2 tests remain opt-in and are not run in CI.
- Page Editor, Character Manager, Progress and Export Center have not been
  exercised against a real project inside ComfyUI.
