# v0.1.0-rc1 Known Limitations

This document describes known limitations and intentional gaps in the
v0.1.0-rc1 release.

## Infrastructure Limitations

- **Standard CI never runs Real ComfyUI, Modal, or S3/R2.** All remote
  integrations are opt-in via environment variables.
- **Modal ComfyUI execution is opt-in only.** Requires Modal SDK,
  pre-populated Volume, and explicit E2E test flags.
- **No automatic checkpoint downloads.** Users must place licensed model
  files on Modal Volume or local ComfyUI installation manually.
- **S3/R2 bucket creation is not automated.** Users must create and
  configure buckets themselves.

## Feature Limitations

- **Full user authentication is not implemented.** Bearer token auth
  exists for Modal worker endpoints, but there is no user account
  system, OAuth, or role-based access control.
- **Web UI operations are limited.** The web interface covers basic
  project management but lacks advanced monitoring, queue management,
  and real-time progress visualization.
- **Image similarity QA is not implemented.** There is no automated
  quality check comparing generated images against reference images.
- **Production autoscaling is not implemented.** Modal workers run on
  a single container with no auto-scaling policy.
- **Signed URL revocation is not implemented.** Once issued, signed
  URLs remain valid until their TTL expires.
- **Long-running ComfyUI production optimization is not implemented.**
  The worker starts and stops ComfyUI per request rather than keeping
  a persistent server.

## Export Limitations

- **PNG/Webtoon export** includes panel images and metadata but does
  not produce print-ready CMYK files.
- **PDF export** uses simple panel layout and does not support
  advanced typography or bleed areas.

## Test Limitations

- **Opt-in E2E tests are skipped by default.** Real ComfyUI, Modal,
  and S3/R2 tests require explicit environment variable setup.
- **Contract tests use mocked S3 clients.** Real S3/R2 integration
  is only tested via opt-in E2E tests.
